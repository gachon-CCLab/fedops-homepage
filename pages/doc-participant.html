FedOps 1.3 / Document

Join federated learning.

Contribute to a published Task using your own local data and Agent Studio.

A concise guide to the 1.3 workflow. The full working manual is available in Notion.

Before you begin

  • The Task has a published release in the Registry.
  • You are signed in to Agent Studio with the account you will use to participate.
  • The required data is available on your device.

1. Request to join

Open the Registry in FedOps Web or Agent Studio. Select a Task and request to join. Wait for the Task Owner to approve your request.

Open Registry ↗ (opens in a new tab)

2. Prepare your Workspace

Open the approved Registry Task in a Workspace. Select a Python environment and run Sync. Follow the Task README to place the required files in its Data Folder.

3. Check participation readiness

Run Check Participation Readiness after preparing your code environment and data. Local readiness and server availability are separate states: you can prepare locally while the server is offline.

4. Start your Client

When participation is ready and the Server is Live, start the Client. Review your local metrics, model flow, and participation history. Do not start duplicate Clients for the same Task on the same device.

5. Finish the session

After the Campaign completes, confirm the final Global Model has been received and finish the Client session. Stopping your Client does not change the server’s saved clients-per-round policy.

If training does not start

  • Check that your participation is approved.
  • Confirm the Workspace belongs to the intended Task.
  • Re-run readiness after changing local data.
  • Check that the Server is Live and a Campaign Run exists.
  • Review any model format or parameter compatibility errors.
