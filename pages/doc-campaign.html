Campaign & Server Management.

Operate shared training for a published Task and track the model version produced by each Campaign.

A concise guide to the 1.3 workflow. The full working manual is available in Notion.

Before you begin

  • The Task has a Published Release.
  • An Initiative Model or previous Global Model is available.
  • The required participants have been approved.

Configure the Campaign

Use FedOps Web to set the training rounds, clients per round, and aggregation strategy. Save the Campaign before starting the FL Server.

Use the strategies available in your current release. Legacy FedMAP, Clustering, and XAI guides should not be assumed to apply to every 1.3 runtime.

Prepare and start the server

Review CPU and memory requests, provision the server resources, and inspect their readiness and logs. Once the runtime and saved Campaign are ready, start the FL Server.

The current working manual includes a step-order item still awaiting confirmation. Refer to the current application and Manual 05 when provisioning resources.

Monitor the active Run

  • Current Campaign Run and communication round
  • Completed and online Clients
  • Global accuracy, loss, and round duration
  • Client metrics visible to the Owner
  • Server and Pod health, logs, and latest events

Review the result

A completed Campaign registers a new Global Model version. Keep metrics separated by Run and check the base model used for the next Campaign. An individual Client stopping does not automatically reduce the saved participation policy.
