Preserve the function contracts

Keep the names, argument order, defaults, keyword-only arguments, and return formats of functions marked FEDOPS CONTRACT. Implement your model behavior inside those contracts.

  • build_model() creates a PyTorch model.
  • train_model() trains the supplied model and returns a finite loss.
  • evaluate_model() returns loss, a primary metric, and additional metrics.
  • load_partition() uses the supplied data_root.
  • predict() returns a JSON object matching the Tool manifest.

Local data remains separate

Use the path passed as data_root rather than hard-coding an absolute local path. Document the required files, features, labels, shapes, and preprocessing in the Task README.

Configure operations in the right place

Rounds, participating Client counts, and the aggregation strategy belong to Campaign/Server Management. Do not place Task IDs, server addresses, credentials, or local absolute paths in the user configuration.

Adapting a 1.2 example

Existing model logic can be useful, but the old models.py, train_torch(), and test_torch() interfaces differ from the 1.3 contract. Use the full Developer Guide as the reference when adapting an example.
