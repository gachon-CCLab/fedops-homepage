Federated AI AgentOps.

FedOps connects model development and federated learning with model reuse, Agent Build, and serving.

A concise guide to the 1.3 workflow. The full working manual is available in Notion.

From local learning to an Agent

FedOps 1.2 focuses on managing Tasks and aggregation servers in FedOps Web, with Clients running in separate environments. The 1.3 workflow brings local preparation, training, federated participation, and Agent delivery into Agent Studio.

Four connected components

ComponentResponsibility
FedOps WebTask publication, participation policy, Campaigns, server operations, and monitoring.
RegistryPublished Tasks, release snapshots, model versions, and participation status.
Agent StudioLocal code, data, Python environment, training, FL Client, and Agent execution.
FL ServerTraining coordination and model update aggregation.

The lifecycle

  1. Create & Register: prepare a Task and its Initiative Model.
  2. Load & Join: publish the Task and approve participants.
  3. Federated Learning: train locally and exchange model updates.
  4. Global Model: register a model version from a completed Campaign.
  5. Build & Serve: select model versions for an Agent and use it locally or through an API.
  6. Improve: retrain a selected component, then validate a new Agent revision.

Versioned models, deliberate releases

An Agent Build keeps its selected model versions fixed. A new Global Model does not automatically replace those versions. Choose the updated component in an Agent Draft and validate it before building the next revision.

The 1.3 manual describes a development workflow. Availability of individual model types and advanced examples should be checked against the release you use.
